# Attention OS morning briefing

Read `$PLUGIN_ROOT/references/MORNING_BRIEFING.md` before producing a briefing.

Build today's story from declared goals, coaching state, fresh Calendar and task
data, current project evidence, relevant communications, and known capacity.
The editorial questions are coverage criteria, not fixed scenes. Label stale,
missing, and inferred inputs.

Identify the real decision, smallest valuable outcome, fixed commitments,
risks/dependencies, and what can wait. Do not mutate systems of record.

When video is enabled, use bespoke explanatory Remotion scenes. Every spoken
word must appear in clause-sized captions with meaningful active-word emphasis.
Derive timing from final narration audio. Use an approved local system voice by
default; external narration is optional and reads credentials only from secure
local storage. Publish only a verified render and retain the prior artifact on
failure.
