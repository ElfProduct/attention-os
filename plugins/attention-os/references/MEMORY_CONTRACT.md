# Memory contract

## Canonical versus runtime

Canonical memory is a small set of human-readable Markdown pages. Runtime state
is a disposable queue pointing to source evidence. A launch card is a bounded
retrieval aid, not a replacement for the canonical pages.

## Evidence order

1. Explicit current declaration or correction.
2. Verified outcome in the relevant system of record.
3. Direct observation with a stated coverage window.
4. Labelled inference supported by multiple observations.
5. Unknown.

Observed behavior alone cannot establish motive, preference, identity, approval,
or off-device inactivity.

## Retention

Retain what changes future decisions: goals, durable constraints, active projects,
decisions, commitments, verified outcomes, corrections, and source-grounded
patterns. Do not retain secrets, full private messages, raw transcripts, browsing
histories, or facts that are better retrieved live.

Every semantic update should be reviewable as one local Git commit. Undo is a
new compensating commit, never history destruction.
